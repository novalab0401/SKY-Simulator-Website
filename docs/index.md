# SKY Simulator Lab

## 전투기 시뮬레이터에서 규칙과 학습 정책을 직접 만들어보기

SKY Simulator Lab은 항공기 전투 시뮬레이션을 사용해 자율 에이전트의 의사결정을
배우고 연습하는 실습 안내서입니다. 사람이 작성한 규칙과 Behavior Tree(BT)를
수정해보고, 강화학습으로 기동 정책을 학습한 뒤, 전투 상황과 리플레이에서
행동 차이를 살펴봅니다.

> **이 프로젝트의 목적:** 현실 전투 효과를 입증하는 것이 아니라, 전투기 시뮬레이션
> 안에서 규칙 기반 조종·BT·강화학습이 어떻게 구성되고 동작하는지 직접 익히는 것입니다.

## 학습 흐름

| 순서 | 배우는 것 | 직접 해볼 일 |
|---|---|---|
| 1. [첫 실행](tutorials/01-first-flight.md) | 전투 설정과 시뮬레이션 한 판 | 조종기와 시나리오를 선택하고 리플레이 열기 |
| 2. [전투 시뮬레이터 구조](tutorials/02-project-and-swarm.md) | 항공기 모델부터 의사결정까지 연결 | 관측→명령→비행→교전 흐름 따라가기 |
| 3. [Behavior Tree](tutorials/03-behavior-trees.md) | 규칙을 우선순위 있는 트리로 표현 | Selector/Sequence 조건과 행동을 바꾸기 |
| 4. [강화학습](tutorials/04-reinforcement-learning.md) | 관측·행동·보상과 PPO/SAC | 이산 setpoint 또는 JSBSim 연속 조종 정책을 학습하고 평가하기 |
| 5. [결과 해석](tutorials/07-evaluate-and-extend.md) | 무엇을 확인할 수 있고 무엇은 말할 수 없는지 | 시드와 지표를 기록하고 작은 실험을 반복하기 |

N:M 편대의 표적 배분이나 외부 알고리즘 연결이 궁금해지면 [선택 확장](tutorials/05-assignment-algorithms.md)으로 넘어가세요. 처음부터 모두 알아야 하는 필수 단계는 아닙니다.

각 장은 **먼저 실행 → 코드에서 확인 → 한 가지 바꾸기 → 관찰한 결과 설명하기** 순서입니다. 기대와 다른 결과도 기록할 가치가 있습니다. 중요한 것은 한 번의 승패만 보고 결론 내리지 않고, 어떤 규칙·보상·초기 조건이 달랐는지 추적하는 것입니다.

## 전투기 시뮬레이터로 무엇을 보는가

시뮬레이터는 항공기의 위치·속도·고도·방향, 상대 기하와 교전 조건을 갱신합니다.
기본 `pointmass`는 빠르게 실험하기 위한 간략화 모델이고, 선택형 `jsbsim`은
JSBSim F-16 백엔드를 사용합니다. 기본 이산 행동은 heading/speed/altitude setpoint를
오토파일럿에 전달합니다. 선택형 연속 제어 실습에서는 JSBSim에 roll/pitch/rudder/
throttle 입력을 직접 전달합니다. 두 모델 모두 학습과 코드 탐색을 돕는 시뮬레이션
환경이지 실제 전투기, 무장, 전술을 완전하게 재현하거나 현실 전투 성능을 보증하는
도구는 아닙니다.

## 현재 제공하는 학습 재료

- 사람이 규칙을 직접 작성하는 `lead` 파일럿과 Python/XML Behavior Tree
- 관측·행동·보상 코드를 읽고 이산 PPO와 연속 PPO/SAC 정책을 학습하는 파이프라인
- 1v1 결투와 N:M 편대 전투 시나리오
- 비행 명령, 기체 움직임, 표적 할당을 살펴볼 수 있는 리플레이
- 여러 기체를 다룰 때 선택할 수 있는 중앙·분산 표적 할당 기능

규칙 기반 조종, Behavior Tree, PPO/SAC는 **행동을 만드는 서로 다른 방법**이지 모든
전투에서 차례로 거쳐야 하는 필수 단계가 아닙니다. 간단한 파일럿은 관측에서 기동
명령까지 한 로직으로 정할 수 있습니다. BT의 Action이 직접 행동을 만들 수도 있고,
특정 BT 분기에서 PPO 정책을 호출하도록 조합할 수도 있습니다. N:M 표적 할당도
여러 기체의 대상을 정하는 한 방법일 뿐, BT가 할당을 맡거나 모든 정책이 할당과
기동을 분리해야 한다는 뜻은 아닙니다.

BT는 규칙을 구조화해 실행하는 방법이며 이 프로젝트에서 BT 자체가 자동으로
학습되는 것은 아닙니다. PPO/SAC 정책은 별도의 학습 과정에서 관측과 보상을 통해
업데이트됩니다. 현재 연속 조종은 JSBSim 전용이며 XML BT Action은 아직 직접
조종축을 출력하지 않습니다. 현재 SKY의 N:M 환경에는 별도 편대 할당 인터페이스가 있지만,
이는 이 시뮬레이터의 구현 경계입니다. 항공기 모델은 선택된 파일럿이 낸 명령으로
비행과 교전 상태를 갱신합니다. 자세한 코드 흐름은
[전투 시뮬레이터 구조](tutorials/02-project-and-swarm.md)를 참고하세요.

## 지금 알고 있는 한계

- `bfm.xml`은 이 프로젝트의 기하 기반 단순화 BT 예제이며, 외부 전술 구현의 직접 포팅이 아닙니다.
- 분산 표적 할당은 현재 문제에 맞춘 적응입니다. 논문 구현 충실도나 보편적인 알고리즘 우위를 자동으로 보증하지 않습니다.
- 저장소의 `models/pursuit_mixed.zip`은 이전 `Discrete(9)` 행동 공간에서 학습된 구형 체크포인트입니다. 현재 이산 `Discrete(27)` 및 연속 `Box(4,)` 정책과 호환되지 않아 새로 학습해야 합니다.
- 작은 시드·판수의 결과는 학습을 위한 관찰 자료이지 일반적인 전투 성능의 증거가 아닙니다.

실제 구현은 [SKY-Simulator GitHub 저장소](https://github.com/novalab0401/SKY-Simulator)에서 확인하세요.

## 바로 시작

시뮬레이터 저장소 루트에서:

```bash
python scripts/run_swarm.py
```

첫 장에서 환경 설치, `combat.yaml` 설정, 1판 실행과 리플레이 확인을 단계별로 진행합니다.

## 사이트 로컬 실행

```bash
pip install -r requirements.txt
mkdocs serve
```

브라우저에서 `http://127.0.0.1:8000`을 엽니다. 정적 문서는 `mkdocs build --strict`로 확인할 수 있습니다.
