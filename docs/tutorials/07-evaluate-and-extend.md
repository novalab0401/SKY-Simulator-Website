# 7. 검증, 결과 해석, 다음 실험

**완료 기준:** 질문에 맞는 지표와 통제 변수를 선택하고, 원자료를 재생 가능한 형태로 남깁니다.

## 먼저 질문을 구체화

“알고리즘이 바뀌나?”와 “어느 알고리즘이 더 잘 싸우나?”는 서로 다른 질문입니다.

| 질문 | 알맞은 확인 방법 |
|---|---|
| 설정한 플러그인이 로드되는가? | `SwarmConfig`/YAML 로더와 레지스트리 테스트 |
| 할당 출력이 달라지는가? | 같은 에이전트·표적 상태로 배정 인덱스 비교 |
| 다양한 초기 조건에서도 차이가 있는가? | 동일 seed 목록에 paired 비교 |
| 승률이 향상되는가? | 충분한 에피소드, 상대/시드 고정, 결과 분포와 불확실성 비교 |
| BT가 더 나은 전술인가? | 같은 환경에서 다판 비교와 로그·분기 확인 |

플러그인이 서로 다른 출력을 내는 것은 교체 기능이 작동한다는 증거이지,
전투 우월성·강인성·실기체 효과의 증명은 아닙니다.

## 공정한 실험의 기본

- **Paired seeds:** 알고리즘마다 같은 seed의 초기 조건을 사용합니다.
- **한 번에 하나:** 파일럿·팀 규모·상대 정책·물리를 동시에 바꾸지 않습니다.
- **충분한 결과 지표:** 승률 포화 시 격추, 손실, 충돌, 미할당과 시간 지표를 확인합니다.
- **분포와 원자료:** 평균 한 숫자만 남기지 말고 에피소드별 JSON/CSV와 설정을 저장합니다.
- **재현 명령:** 명령줄, 시작 seed, 에피소드 수와 적용한 커밋을 기록합니다.
- **정직한 표현:** 표본이 작거나 승률 차이가 불명확하면 “탐색 결과”라고 씁니다.

## 결과 묶음에 남길 것

프로젝트의 `scripts/compare_assigners.py`는 `--out-dir`을 주면 비교 결과를 한 디렉터리에 기록합니다.
알고리즘 전환이 보이는 초기 할당 그림과 리플레이도 재사용 가능한 증거입니다.

결과 페이지에 최소한 다음을 적습니다.

1. 실험 목적과 비교한 가설
2. 팀 규모·파일럿·상대 행동·물리 백엔드
3. 알고리즘 설정과 통신/센싱 반경
4. seed 범위와 판 수
5. 승리·격추·손실·할당·통신 관련 결과
6. 한계와 이번 결과로 말할 수 없는 것
7. JSON/CSV, 그림/리플레이, 재실행 명령

## 다음 연구 질문

- 강한 red Brain을 상대로 할당기가 전투 결과에 기여하는가?
- 통신 그래프가 끊기거나 반경이 달라질 때 중복·미할당은 어떻게 변하는가?
- 4v20에서 승률이 모두 0이라면, 어떤 지표가 여전히 알고리즘 차이를 보여주는가?
- 동일한 BT 분기 선택이 실제 손실/격추를 개선하는가?
- 새 PPO 체크포인트가 `lead` baseline을 여러 시드에서 일관되게 넘는가?

## 추천 확장 순서

1. 먼저 `combat.yaml`에서 실험을 재현합니다.
2. 기존 구현을 수정하기 전에 관측과 테스트를 추가합니다.
3. 작은 설정·짧은 실행으로 정확성을 확인합니다.
4. 전체 paired 실험과 리플레이를 생성합니다.
5. 사이트 튜토리얼이나 결과 문서에 발견한 제한과 근거를 기록합니다.

축하합니다. 이제 설정을 사용하는 단계에서, 코드 변경을 설계하고 실험으로 검증하는 단계로 넘어갈 수 있습니다.
