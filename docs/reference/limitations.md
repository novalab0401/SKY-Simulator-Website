# 시뮬레이터의 범위와 한계

SKY의 목적은 전투기 시뮬레이션에서 규칙 기반 조종, Behavior Tree, 강화학습을
배우고 직접 실습하는 것입니다. 현재 제공하는 모델·도구가 의미하는 범위를
과장하지 않도록 아래 한계를 함께 확인하세요.

## 모델·기동

- 기본 `pointmass`는 학습을 빠르게 반복하기 위한 간략화된 기동 모델입니다. JSBSim은 별도 의존성이 필요한 선택형 F-16 백엔드입니다.
- 기본 `discrete` 행동은 heading/speed/altitude setpoint이며, 오토파일럿을 거쳐 비행합니다.
- `continuous` 행동은 JSBSim에서만 지원하는 정규화된 roll/pitch/rudder/throttle 입력입니다. 조종면·스로틀 명령이 실제 F-16 비행 제어계를 완전하게 대체하거나 제한·손상·엔진 고장 등을 모델링한다는 뜻은 아닙니다.
- 현재 XML/Python BT 예제는 기존 setpoint 명령을 생성합니다. 연속 제어 벡터를 직접 출력하도록 연결된 것은 아닙니다.
- 연속 PPO/SAC 학습 경로가 구현되어 있어도 정책이 안정적으로 조종하거나 우수한 기동을 학습했다는 보장은 없습니다.
- 현 무장/WEZ 시스템은 유도 미사일 비행, 단발 확률적 격추, 대응수단 모델을 포함하지 않습니다.
- 이산 `Discrete(27)`과 연속 `Box(4,)`는 서로 다른 관측·행동 계약입니다. 과거 체크포인트는 학습 알고리즘, 상태 차원, 행동 공간이 맞아야 합니다.
- Windows에서 JSBSim 설치, 단일 에피소드 실행과 PPO/SAC 학습이 모두 확인된 상태는 아닙니다. 플랫폼 지원은 실제 설치·테스트 범위로 제한해 주장해야 합니다.
- 따라서 F-16 백엔드가 있더라도 현실의 공중전 성능이나 전술 효과를 재현한다고 볼 수 없습니다.

## BT

- 프로젝트는 자체 BT 엔진과 지원 XML vocabulary를 사용합니다.
- 임의의 BehaviorTree.CPP tree/plugin 호환을 제공하지 않습니다.
- 다른 가지가 실행되는 것을 확인하는 테스트는 전투 효율 검증과 다릅니다.

## 분산 할당

- `first_claimed`, `cbba`, `grape`는 현재 목표 문제에 맞춘 알고리즘 적응입니다.
- 메시지는 동기적이고 신뢰성 있게 전달되는 것으로 모의합니다. 실제 latency, loss, 비동기 clock, 복구는 모델링하지 않습니다.
- 통신 그래프가 끊기면 여러 컴포넌트가 같은 target capacity를 선택할 수 있습니다.
- 월드 상태 업데이트와 점수 계산은 중앙 실행입니다.

## 실험 수치

- 소수 에피소드의 승률 차이는 일반적인 조종기·알고리즘 우위의 증거가 아닙니다.
- 적 전멸 조건이 달성되지 않아 모든 승률이 0이면, 그 지표는 비교에 정보가 없습니다.
- 각 비교 결과는 시드 범위, 파일럿, 상대 정책, 백엔드, 임무 규모와 함께 학습 관찰 자료로 해석해야 합니다.
- 테스트 통과는 구현 계약이나 테스트 사례가 맞았다는 뜻이지, 모델 충실도·전술 우수성·논문 재현을 보증하지 않습니다.
- 연구 결과를 주장하려면 질문에 맞는 여러 시드, 학습/평가 데이터 분리, 설정과 체크포인트 보존, 비교 기준선, 적절한 불확실성 분석이 추가로 필요합니다. 제공된 스크립트와 smoke test만으로 연구 결론이 검증되는 것은 아닙니다.

이 한계는 학습에 쓸 수 없다는 뜻이 아닙니다. 규칙과 정책이 시뮬레이션에서
어떻게 동작하는지 배우되, 관찰 결과가 뒷받침하는 범위까지만 설명하기 위한
경계입니다. 이 범위를 넓히려면 질문에 맞는 별도 검증과 근거가 필요합니다.
